# Пользовательские подключения GitHub/GitLab (#86)

При включённой авторизации сервер подключает стандартный CredentialProvider.
`POST /api/connections` принимает `remote_url`, `token`, `expires_at` (Unix seconds).
Ответ и `GET /api/connections` содержат только ID, URL, даты и состояние.
`POST /api/connections/{id}/check` проверяет чтение HEAD; `DELETE` отзывает
подключение и удаляет шифротекст. Импорт/refresh принимает только ID в
`credential_ref`; токен не попадает в снимок, модель, события или историю.
Создание подключения сохраняет его; доступ проверяется отдельно перед импортом.

Поддержаны github.com и gitlab.com, включая вложенные группы GitLab. Для
собственной установки оператор указывает имя хоста в `PROVERYALKA_GITLAB_HOST`.
Сервер проверяет DNS и открывает HTTPS-соединение только с публичным адресом.
Все операции с хостингом используют GET. Поддерживаются следующие токены.

- GitHub fine-grained PAT для одного репозитория, Contents: read-only (Metadata
  read-only назначается GitHub). [Документация](https://docs.github.com/en/rest/repos/contents).
- GitLab project access token с read_api и ролью Reporter для нужного проекта.
  [API репозиториев](https://docs.gitlab.com/api/repositories/).

Приложение не может по непрозрачному токену доказать отсутствие дополнительных
прав на стороне хостинга. Оно выполняет только чтение и ограничивает токен одним
точным каноническим URL. Не выдавайте широкие права при создании токена.

`PROVERYALKA_CONNECTION_KEY` — Fernet-ключ из переменной окружения. Генерация:

```sh
python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'
```

Храните его вне БД и Git; не публикуйте вывод. При отсутствии ключа создание
подключений возвращает 503. Потеря/замена ключа делает старые подключения
нечитаемыми: нужно отозвать их и создать заново; автоматической ротации нет.
Шифротекст включает владельца, ID и URL для проверки привязки. Отключение
обнуляет secret, но оставляет историю снимков. Истечение проверяется при каждом
использовании. Отзыв у провайдера проявляется безопасной ошибкой доступа при
проверке/импорте; сетевые ошибки не удаляют историю. Уже отправленный запрос
отозвать задним числом нельзя. Перед следующим запросом архива права проверяются
повторно. Authorization удаляется при любом redirect, включая тот же хост.

Сервер не сохраняет секрет в браузере; будущий UI #73 должен отправлять его
однократно по HTTPS, очищать поле и не использовать localStorage/sessionStorage.

Проверки: `tests/test_connections.py` прогоняет оба хостинга через настоящий
CredentialProvider/HTTP API/SQLite/индексатор с подменённым внешним HTTP, проверяет
чужой ID, другой host/repo, срок, потерю ключа, отзыв и сохранность истории.
Реальный приватный проект не проверялся: тестовые токены хостингов не предоставлены.
