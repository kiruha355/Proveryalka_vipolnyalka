# Пользовательские данные (#80)

В режиме `PROVERYALKA_AUTH_ENABLED=1` все `/api/*` требуют cookie-сессию,
изменения — Origin и CSRF. Источники, изображения, снимки репозитория, модели,
версии, проверки, генерации и тестовые запуски наследуют владельца через
неизменяемую связь с `sessions.owner_id`. Нормализация исключает рассогласование
копий owner_id в дочерних таблицах. Чужой и отсутствующий ID возвращают 404.
Проверки выполняются зависимостью FastAPI после разрешения параметров маршрута,
до чтения тела обработчиком/запуска операции. Защищены файлы, ZIP, логи и SSE.
Сессия повторно проверяется при выдаче каждого фрагмента ответа.

Существующие локальные чаты после миграции остаются без владельца и недоступны
через пользовательский API. Администратор сначала регистрирует нужный аккаунт,
затем останавливает сервер и явно выполняет:

```sh
python -m proveryalka.auth.assign_legacy --database /path/to/app.db --email owner@example.com
```

Команда назначает только ещё не принадлежащие никому чаты со всеми дочерними
данными. Регистрация первого пользователя ничего автоматически не присваивает.
Локальный режим без авторизации сохранён для одного оператора; его нельзя
выставлять в общедоступную сеть.

MCP включается отдельно. `POST /api/auth/mcp-tokens` принимает `model_ids` и
`expires_in` (60–2592000 секунд), требует cookie/CSRF и владения каждой моделью.
Возвращает секретный `token` однократно и публичный `token_id` для
`DELETE /api/auth/mcp-tokens/{token_id}`. В БД хранится только SHA-256 токена.
MCP принимает его через Authorization: Bearer, проверяет пользователя, срок,
проект и разрешённые сервером инструменты. Токен MCP не работает как cookie.
В пользовательском режиме transport stateless: общие MCP session IDs не дают
перенести идентичность. Локальный `PROVERYALKA_MCP_MODEL_IDS` не раздаётся
пользователям. Ограничения loopback/host/нагрузки остаются в силе; удалённый
публичный MCP deployment в эту задачу не входит.

`tests/test_ownership.py` проверяет два аккаунта, закрытые HTTP/SSE/file/ZIP/log
маршруты и отмену, раздельную идемпотентность, явную миграцию старых чатов,
выдачу/отзыв MCP-токена и настоящий SDK transport с проектными разрешениями.
