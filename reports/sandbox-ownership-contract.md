# Владение контейнерами песочницы (#48)

`DockerSandbox` получает случайный `owner_id` на экземпляр. Каждая invocation имеет уникальное имя контейнера (даже при одинаковом `run_id`), метки `proveryalka.codegen.test_run` и `proveryalka.codegen.owner`. `kill` и финальный `rm -f` сначала проверяют обе метки и используют неизменяемый Docker ID.

`cleanup_orphans()` рассматривает только exited-контейнеры своего owner, перепроверяет метки/состояние через inspect и исключает собственные активные invocation. Удаляет без `-f`; конкурентный restart приводит к отказу удаления. Возвращает количество успешных удалений. Общая метка приложения, PID другой машины или отсутствие локального процесса не доказывают orphan.

Контейнеры прежнего процесса и legacy-контейнеры без owner автоматически не удаляются. Они требуют отдельного решения оператора после проверки владельца. В частности, старт сервера B не очищает контейнеры сервера A. Один backend worker на SQLite остаётся требованием; этот фикс не разрешает совместное выполнение двух backend над одной БД.

`CodegenService.start()` сохраняет cleanup task; `close()` отменяет и дожидается только своего task. Временный MCP-адаптер `cleanup_orphans -> 0` после интеграции убрать: использовать обычный DockerSandbox.
