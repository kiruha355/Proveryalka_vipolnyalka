Общая архитектура

HTTP API управляет отдельными запусками аналитика, TLC и тестов. Агент и ядро проверки связаны строгими контрактами, а не свободным текстом ответа LLM.

Mput13 · UISOKLY6 · APIkiruha355 · агентkontar0 · TLC

Описание → модель → проверка

Вопросы и явная правка возвращают пользователя в диалог. Проверка запускается вручную; объяснение получает уже сохранённый отчёт той же версии.

LLM не объявляет результат TLC сам. В текущем подписочном runtime нет автономного цикла с произвольными инструментами: следующий ход получает сохранённые требования и подходящий отчёт по hash модели.

Ядро kontar0

BehavioralModel задаёт конечную модель поведения. SANY проверяет сгенерированную спецификацию, TLC исследует её состояния. Кэш не заменяет отчёт другим результатом: ключ учитывает модель, свойства, параметры и движок.

Данные и неизменяемость

Версия, проверка, генерация и тестовый запуск — разные сущности. По этим связям экран показывает результат выбранной версии, а старые отчёты сохраняются после исправления.

Основной registry включает image_sources → image_analyses (007) и repository_snapshots → repository_files / repository_source_contexts (008). Изображение не притворяется текстовым Source; выбранные строки репозитория создают настоящий ограниченный Source.

Генератор и песочница

Генерация синхронно создаёт файлы; исполнение тестов — отдельная асинхронная операция. Контейнер получает сохранённый проект и возвращает отчёт, а не право менять модель.

Генерация при неподтверждённом результате TLC требует явного allow_unverified в реализации. Эта продуктовая политика ещё не принята пользователем.

Новые подключения и запуск

Источники #45/#46 и MCP #47 подключены к общему backend. Изображения и репозитории доступны через API; новые клиентские экраны для них пока не добавлены.

Четыре MCP-инструмента: get_model, check_behavior, get_tests, compare_with_code. Последний проверяет точную сохранённую генерацию через штатную песочницу; произвольный код пока не поддерживается.

Граница интеграции. Основные текстовый диалог, TLC, генерация и файлы связаны в PR63–66. PR67 (изображения), PR68 (MCP), PR69 (репозитории) и PR70 (launcher/CI) объединены в локальную поставку. Общая проверка: 513 backend PASS с настоящими TLC/Docker, frontend 36 PASS, extensions 108 PASS. Новые API не означают готовность клиентских экранов изображений/репозиториев. Корпусная оценка качества аналитика #30 и исследование мультиагентного ревью #42 не выдаются за готовые компоненты.

Запуск и CI

Delivery переиспользует существующий create_app и его жизненный цикл. CI разделяет клиент, проверку моделей и исполнение кода; ручной LLM-прогон не подменяет эти обязательные проверки.

Схема CI показывает конфигурацию jobs, а не заявление о состоявшемся запуске всех этих jobs на GitHub. Локальные доказательства и непроверенные уровни перечислены в delivery/evidence.md.
