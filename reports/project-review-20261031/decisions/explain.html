Решения по клиенту Проверялки

Клиент помогает описать процесс, уточнить правила и разобрать найденную ошибку. Человек определяет смысл правил и принимает исправление; агент строит модель и объясняет, TLC проверяет её.

Пользовательский путь

  1. 01ОписаниеТекст или TXT / MD / DOCX.
  2. 02Уточнения в чатеАгент спрашивает недостающие условия; ответы сохраняются.
  3. 03Просмотр моделиПравила, источники, этапы и значения переменных.
  4. 04«Проверить»Пользователь вручную запускает TLC для выбранной версии.
  5. 05Разбор и правкаТрасса → объяснение → явное изменение правила → новая версия и проверка.
  6. 06Проект и тесты«Согласовать для кода» → генератор по шаблонам без LLM → файлы / ZIP → отдельный запуск pytest в Docker.

Согласование означает «модель отражает требования, использовать для кода»; результат TLC оно не заменяет. Вопрос GPT о файле использует проверенные сохранённые байты и не меняет требования или версии. Полная последовательность · Все семь схем команды.

Почему отменённая заявка исполнялась

В реальном прогоне пользователь уточнил условие исполнения: approved=true и cancelled=false. Агент создал версию 2; повторный TLC подтвердил проверяемое правило. Исходная версия и её контрпример сохранились.

Принятые решения

ПредметРешение и смысл
ЧатНазвание «чат» сохраняем. В нём должны быть исходные сообщения, уточнения, объяснение и последующие указания пользователя. Одного журнала проверок недостаточно.
Агент и TLCАгент интерпретирует текст; результат проверки сообщает TLC. Исправление правила требует явного указания пользователя. Самостоятельного ReAct-цикла с выбором инструментов сейчас нет.
Запуск проверкиРучное действие после просмотра модели. Основная кнопка проверяет все правила версии; выбор технических лимитов из основного экрана убран. Незавершённая проверка не считается успехом.
Версии и подтверждениеИзменение создаёт новую версию. «Подтвердить модель» означает принять интерпретацию требований для генерации проекта. Это отдельное решение от результата TLC; проверять можно до подтверждения.
ДиаграммаПоказываем этапы процесса и связи, а не все сочетания флагов. Точные значения и изменения — в инспекторе и трассе. Проекция явно называет скрытые переменные.
Управление и видРегулируемая горизонтальная ширина панелей, компактная шапка, разворачивание графа. Умеренные скругления 4–6 px; статусы без таблеток. Финальную удобность ещё проверяем вместе.
ГенерацияPython + FastAPI + pytest, отдельный PR. Генератор сейчас детерминированно переводит модель в код; тесты запускаются отдельно в Docker. Успех pytest не отменяет найденное TLC нарушение.
Провайдер и GitHubПока используем GPT-подписку через локальный runtime; API МАИ отложен. Воркеры — GPT-6.1-Sol xhigh после лимитов Claude. Результаты оформляем draft PR, без служебной атрибуции Claude.

Экраны второго просмотра

Выбранный узел или файл не становится контекстом агента автоматически. Действия обсуждения добавляют конкретный результат в черновик сообщения; пользователь редактирует и отправляет его сам.

Что проверено и что осталось

Общая локальная интеграция — draft PR #71. Backend: 513 PASS, 0 skipped, с настоящими TLC и Docker. После последней правки UI: 38 frontend PASS + 1 opt-in skip, 108 extensions PASS, types/build PASS (квитанция UI).

Основной браузерный сценарий #39/#49 выполнен: GPT → v1 VIOLATED → явная правка guard → v2 HOLDS → согласование → 16 файлов / ZIP 20 392 байта → read-only GPT-вопрос о файле → refresh → Docker 54/54 PASS. Этот прогон предшествует подключению PR67–70; общая интеграция проверена отдельно. Квитанция.

Открыты корпус #30, установка на чистой машине и пользовательская визуальная приёмка. Native screenshot/AX живого сценария завершился timeout; сохранённый DOM/render не заменяет screenshot. Скриншоты выше показывают revision-2 и не включают последние правки UI.

Открытое продуктовое решениеВ реализации есть явный allow_unverified, но политика генерации при VIOLATED или незавершённой проверке пользователем ещё не принята. В живом сценарии этот обход не использовался.

Наличие локальных доказательств не означает GitHub merge, CI green, закрытие issues или пользовательскую приёмку. Текущий стенд и ручной сценарий.
