# Ход работы агента

В чате добавлен сворачиваемый журнал фактических операций. Сводка показывает текущий этап; раскрытие - сохранённые события, их время, исход попытки и длительность при известных серверных timestamps. API: GET /api/sessions/{id}/agent-runs?limit=50&before=cursor. Связи input_entry_id/reply_entry_id не восстанавливаются по похожим текстам.

События activity создаются непосредственно на границах подготовки контекста, вызова модели, получения ответа, валидации, повторной попытки и сохранения. Ошибка наблюдателя не запускает модель повторно. ContextVar разделяет параллельные запуски. События хранятся в существующем run_events; миграция и выдуманный backfill не нужны. У старых запусков неизвестные timestamps остаются null. Endpoint исключает произвольные provider/tool payloads и внутренние рассуждения; output text представлен числом символов, сами ответы остаются в чате.

Референсы для поведения: раскрываемый проверяемый журнал действий и результатов у [Codex](https://openai.com/index/introducing-codex/) и принцип прозрачности этапов у [Anthropic](https://www.anthropic.com/research/building-effective-agents). Оба launch/engineering материала исторические; используем принципы, не заявляем идентичность текущему UI этих продуктов. Журнал не изображает автономные действия, которых у нашего подписочного аналитика нет.

Граф занимает свободную высоту панели. В обычном виде осталось одно нижнее разворачивание; верхняя полоса убрана. В раскрытом графе доступны крестик, Escape и возврат фокуса. Заголовок, вкладки и контролы закреплены; инспектор и данные прокручиваются в своих областях.

Подробности worker-проверок: frontend/HANDOFF.md и layout/verification.md. Итог: backend522 PASS с обязательными TLC/Docker; frontend50 PASS +1 opt-in HTTP skipped; extensions113 PASS. Настоящий новый GPT-вызов через браузер дал модель и полный сохранённый trace за37с; второй browser profile восстановил тот же единственный trace после загрузки страницы. Receipt: acceptance/receipt.json. Пользовательская приёмка остаётся отдельной.

Подписи петлевых переходов разведены в устойчивые верхние/нижние дорожки. Фон подписей непрозрачен, длинный текст переносится; IDs переходов/выбора/шагов трассы сохранены.

В UI8 также исправлен порядок слоёв: подписи z-index3 выше SVG-переходов1/2, поэтому линия не проходит поверх текста. Итоговый native скриншот: acceptance/graph-labels-ui8.png.
