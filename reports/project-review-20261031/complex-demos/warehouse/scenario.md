# Складской заказ и потерянный резерв

Учебный сценарий использует целочисленные остатки, этапы заказа, отдельную оплату и одновременные присваивания. В заказе 2 единицы, всего на складе 3.

Ожидаемая ошибка первой версии: Reserve переносит 2 единицы из available в reserved; Cancel обнуляет reserved, но не возвращает товар в available. Суммарно после Reserve→Cancel остаётся 1 учтённая единица вместо 3. Это ожидаемый тестовый oracle, фактический результат TLC фиксируется отдельно.

Явная правка второй версии: Cancel присваивает available=available+reserved одновременно с reserved=0. Выражение читает значение reserved до перехода. Нельзя последовательно прочитать уже обнулённый резерв.

Проверяемые свойства: сохранение общего количества товара; отсутствие отгрузки у отменённого заказа; оплата перед отгрузкой. Свойства не должны автоматически попадать в guards и тем самым скрывать учебную ошибку.

Все изменения данных приложения выполняются через native UI. Записанный исходный запрос — initial.txt. Настоящие вопросы, ответы, спецификации и результаты сохраняются в соседних JSON после завершения шагов. Заявлений о Docker run до отдельного разрешения root нет.
