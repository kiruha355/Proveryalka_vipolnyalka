Это настоящий новый диалог GPT по подписке, три аналитических хода и два ручных TLC-запуска через native UI. Никаких fixtures вместо модели или HTTP POST-скриптов. Исходный запрос — initial.txt, полный диалог — dialogue-final.json, точные IDs/hash/статусы — receipt.json.

## Что показать за 2–3 минуты

1. Открыть нарушение v1. Сначала available=3, reserved=0, shipped=0. Reserve даёт 1+2+0=3. Cancel обнуляет reserved, но available остаётся 1: сумма 1 вместо 3. Настоящая трасса **Reserve→Cancel**.
2. В чате показать фактический вопрос «Каково начальное значение paid: false или true?» и адресный ответ paid=false. У модели пять переменных, четыре действия, три свойства.
3. Выбрать v2: явная правка добавила available=available+reserved одновременно с reserved=0. Остальные три перехода и все свойства побайтово совпадают с v1.
4. Открыть проверку v2: **все три свойства PROPERTY_HOLDS**, полный обход по 6 достижимых состояний для каждого. В v1 сохранение количества PROPERTY_VIOLATED (4 состояния до остановки на контрпримере), два остальных свойства HOLDS (по 6 состояний).
5. Открыть файлы: v2 согласована для кода, создан настоящий Python/FastAPI/pytest-проект из 16 файлов; ZIP26539 байт, SHA всех 16 файлов сверены с manifest. В generated-rules.py видно исправленное присваивание.

## Границы

Автоматические объяснения обеих проверок готовы; v1 прямо объясняет потерю резерва и сумму 1 вместо 3. Docker-тесты этим worker не запускались; root проводит их отдельно. В момент просмотра Files сообщал отсутствующий sandbox image, настройки Docker не менялись. Native snapshot одной попыткой дал timeout15000ms, поэтому PNG не подменяется HTML-рендером. В ZIP доказан read-only HTTP-export; UI download был нажат, но browser receipt не появился.

Код приложения, сервер, зависимости, git/PR не менялись. Собственная вкладка закрывается после передачи root; пользовательские вкладки сохранены.
